## 3 正式官网部署步骤

1. **确认基线。** 9 月 18 日交付核对时，正式官网的产品页与目录脚本和 `943ac39` 的根目录版本一致。部署前再次确认没有后续改动；如有差异，先合并，不直接覆盖。如尚未部署 9 月 17 日版本，先补齐上一版更新和 AT-200、AT-300 图片。
2. **备份现网。** 将 `products/index.html`、`assets/catalog.js` 备份到网站公开目录之外，并记录时间与位置。如果现网已有同名 F6 图片，也先备份。保留现有表单配置，不上传或公开企微 Webhook。
3. **校验交付包。** 在解压后的包目录执行下面的校验命令，3 个文件应全部通过。`release.json` 记录来源提交、路径转换及文件校验值，可留作交接记录。

```bash
# Linux
sha256sum -c SHA256SUMS.txt
# macOS
shasum -a 256 -c SHA256SUMS.txt
```

4. **在测试副本验证。** 将这 3 个文件合入完整官网副本，通过 HTTP 或 HTTPS 检查。本包不是完整网站，不要单独启动增量包，也不要双击 HTML 以 `file://` 打开。
5. **按原有方式发布。** 使用现有流水线、SFTP 或服务器面板。优先在新版本目录合并后原子切换；必须逐文件上传时，依次上传 F6 图片、目录脚本，最后替换产品页。保持原有权限，不做删除式全站同步。
6. **刷新缓存。** 如使用 CDN，刷新 `/products/`、`/products/index.html`、`/assets/catalog.js` 及新图片路径。确认网页加载 `/assets/catalog.js?v=20260918-1`，再用无痕窗口验收。若 CDN 忽略查询参数，须刷新脚本路径，不能只在页面网址后加参数。
