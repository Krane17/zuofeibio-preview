## 4 正式官网部署步骤

**第一步　确认发布位置**

由 IT 确认 `www.zuofeibio.com` 对应的网站根目录或现有发布流水线，以及是否使用 CDN。沿用当前静态站点发布方式；本次不需要 npm 构建、数据库迁移、修改 DNS、证书或重新部署 Apps Script。不要在生产目录直接拉取 GitHub 预览站源码并整体覆盖。

**第二步　备份与比对**

将现网 `products/index.html`、`assets/catalog.js` 备份到网站公开目录之外，记录时间和备份位置。若同名新图片已存在，也先备份。比对官网近期变更，确认可使用本增量包；同时保留当前 `assets/form-config.js`，不要替换或公开企微 Webhook。

**第三步　检查更新包**

确认 `site/` 下恰好有清单中的 4 个文件，文件名大小写一致。`release.json` 记录来源提交和包内路径转换；`SHA256SUMS.txt` 记录 4 个文件的 SHA-256。可在解压目录执行以下任一校验命令，应全部通过：

```bash
# Linux
sha256sum -c SHA256SUMS.txt
# macOS
shasum -a 256 -c SHA256SUMS.txt
```

**第四步　在测试环境验证**

优先将文件合入官网副本，通过 HTTP 或 HTTPS 测试，不要双击 HTML 使用 `file://` 打开。测试环境应按根目录提供 `/products/`、`/assets/`、`/media/`，且具备原站未改的其他资源。此包是增量包，单独解压并启动它不能得到完整网站。

**第五步　上传并发布**

使用现有发布流水线、SFTP 或服务器面板，将 `site/` 内文件按相对路径放入官网。优先在新版本目录内合并后原子切换。若必须逐文件替换，先上传两张 PNG，再替换 `assets/catalog.js`，最后替换 `products/index.html`，缩短新旧内容混用时间。保持现有文件权限，不使用删除式全站同步。

**第六步　清理缓存**

如使用 CDN，刷新 `/products/`、`/products/index.html` 和 `/assets/catalog.js` 的相关缓存。核实产品页加载的是 `/assets/catalog.js?v=20260917-2`，然后用无痕窗口或强制刷新验收。若 CDN 忽略查询参数，必须刷新对应脚本路径；仅在页面网址追加参数不一定能更新脚本缓存。

| 现象 | 检查与处理 |
| --- | --- |
| 仍显示 99 款 | 核对上传的站点目录、HTML 和脚本版本，并刷新 CDN |
